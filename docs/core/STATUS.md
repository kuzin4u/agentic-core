## Заделы
- **Правило: ожидание CI — только `gh pr checks N --watch`**, одной командой, без циклов опроса `gh` (решение владельца 13.10.2026: в сессии 4 цикл опроса исчерпал лимит GitHub API 5 000 запросов в час). Записано в `/finish` п. 8; перенести в `/finish` платформы и агента.
- ~~**v0.3.0 — экспорт `isWeakEd25519`**~~ сделано: П5.1 `fef4932` (PR #21), вариант А — `isWeakEd25519(x: Buffer)`. Было: экспорт из ядра (реэкспорт из `src/ed25519.ts` в `index.ts`): платформа заменит свою (`src/registry/keys.ts`), агент — свою копию (`src/agent/signer/weak.ts`); сейчас одна логика в трёх местах, сверка ядро ↔ платформа — 22 878 входов без расхождений (PR #17).
- ~~**v0.3.0 — векторы слабых ключей**~~ сделано: П5.1 `fef4932`, раздел `ed25519_weak_keys` (19 случаев). Было: векторы слабых ключей разделом `vectors/vectors.json` (8 точек малого порядка, неканонические записи, y = p + 3, точка не на кривой) — через `/decision`: новый раздел добавляет требование к переносам ядра (К3), это не патч.
- **Внешний якорь журнала — к PS-06 или SEC-2** (К6 п. 9, ревью #19). Удалённый суперпользователем хвост и цепочку, пересчитанную целиком, по одной таблице `core_journal` не обнаружить. `verify({ seq, hash })` сверяет цепочку с якорем, а хранение и подпись якоря — у потребителя: отдельное хранилище или подписанная выписка (платформа — журнал согласий PS-06; подпись выписки — SEC-2).
- **Проверка журнала частями — к PS-06** (ревью #19, К2.3). `verify()` и `extract()` читают цепочку целиком через `store.all()`: для журнала согласий с тысячами записей на клиента это нормально, для общей цепочки — нет. Нужны постраничная проверка (`seq` диапазонами) и проверка «от последнего якоря» — от `anchor.seq` вперёд, без чтения начала.
- **PS-05 — кэш разбора ключа.** `ed25519Verifier` разбирает точку на каждом вызове: ≈ 3,3 мс против ≈ 0,8 мс без проверки (одно возведение в степень для корня). Для эмулятора и стенда несущественно; для шлюза — кэш по строке ключа.
- **Подставная поломка конкурентного теста nonce на PG** (ревью перед `/finish`, владелец 15.10 — в заделы). Тест «20 одновременных seen одного nonce» на PG есть и зелёный (`tests/pg-nonces.test.ts`), но красным на PG не показан: поломка «проверка и запись двумя командами» (`SELECT`, затем `INSERT`) → красный CI → откат. Единственная PG-гарантия CO-2 без поломки — к следующей задаче, где трогаются nonce (PS-05 или CO-4).
