# Журнал решений agentic-core

### К1. Отдельный пакет для общих механизмов
- **Решение:** механизмы, нужные двум и более проектам, живут в `agentic-core`; проекты подключают фиксированную версию.
- **Почему:** иначе журнал согласий, удержания и подпись были бы написаны в ПС-платформе, агенте, marketplace-api и НСВР по отдельности и разошлись бы.
- **Что меняет:** РП14 в ПС-платформе, Р16 в агенте, Н3 в НСВР, записи для marketplace-api.
- **Отменяет:** —

### К2. Нейтральные имена
- **Решение:** API пакета без предметных слов: `HoldLedger`, `HashChainJournal`, а не `MandateBudget`, `EscrowAccount`.
- **Почему:** один механизм удержаний обслуживает и бюджет мандата, и эскроу; предметная оболочка — у потребителя.

### К3. Тестовые векторы как контракт
- **Решение:** `vectors/vectors.json` — нормативная часть пакета; перенос на другой язык обязан их проходить.
- **Почему:** стек `buyer_agent` не зафиксирован; ядро должно оставаться единым по смыслу независимо от языка.

### К4. Подключение пакета
- **Решение:** до публикации в реестр пакетов — git-зависимость с тегом версии (`"@kuzin4u/agentic-core": "git+https://github.com/kuzin4u/agentic-core.git#v0.1.0"`).
- **Почему:** не нужен отдельный реестр; версия фиксируется тегом.
