# Журнал решений agentic-core

### К1. Отдельный пакет для общих механизмов
- **Решение:** механизмы, нужные двум и более проектам, живут в `agentic-core`; проекты подключают фиксированную версию.
- **Почему:** иначе журнал согласий, удержания и подпись были бы написаны в ПС-платформе, агенте, marketplace-api и НСВР по отдельности и разошлись бы.
- **Что меняет:** РП14 в ПС-платформе, Р16 в агенте, Н3 в НСВР, записи для marketplace-api.
- **Отменяет:** —

### К2. Нейтральные имена
- **Решение:** API пакета без предметных слов: `HoldLedger`, `HashChainJournal`, а не `MandateBudget`, `EscrowAccount`.
- **Почему:** один механизм удержаний обслуживает и бюджет мандата, и эскроу; предметная оболочка — у потребителя.

### К3. Тестовые векторы как контракт
- **Решение:** `vectors/vectors.json` — нормативная часть пакета; перенос на другой язык обязан их проходить.
- **Почему:** стек `buyer_agent` не зафиксирован; ядро должно оставаться единым по смыслу независимо от языка.

### К4. Подключение пакета
- **Решение:** до публикации в реестр пакетов — git-зависимость с тегом версии (`"@kuzin4u/agentic-core": "git+https://github.com/kuzin4u/agentic-core.git#v0.1.0"`).
- **Почему:** не нужен отдельный реестр; версия фиксируется тегом.

### К5. Протокольный слой ПАО — подмодуль `/pao`
- **Решение:** типы, клиент и сервер-заглушка ПАО v1.1 живут в отдельном подмодуле `@kuzin4u/agentic-core/pao`. Типы генерируются из копии `spec/agent-protocol.yaml` (источник — agentic-ps-platform@0bc924e, sha-256 `e6725aa4270155be5d0606cb366ca095fedc13a7d4e6c7b9500d25addf945ecb`); сгенерированный файл коммитится. YAML разбирает пакет `yaml`, подключённый только как devDependency генератора; во время выполнения внешних зависимостей по-прежнему нет. Предметные имена ПАО (`Mandate`, `MANDATE_*` и др.) допускаются только в `/pao`; основной вход пакета остаётся нейтральным.
- **Почему:** CO-3 по совместному плану ред. 3 — одна генерация типов на платформу (PS-02) и агента (AG-02), чтобы поля не могли разойтись. Переименование протокольных типов в нейтральные снова создало бы расхождение, ради устранения которого CO-3 и ставится. Копия спецификации в репозитории позволяет собирать и проверять пакет в CI без соседнего репозитория, а хэш показывает, от какой редакции ПАО сгенерированы типы.
- **Что меняет:** CLAUDE.md (таблица модулей, правило нейтральности, стек, раздел «Спецификация ПАО»), README (подключение `/pao`), ROADMAP (журнал изменений), STATUS. В PS-02 платформы и AG-02 агента типы ПАО импортируются из `@kuzin4u/agentic-core/pao`.
- **Отменяет:** — (уточняет К2 для подмодуля `/pao`, К2 остаётся в силе)

### К7. ПАО 1.2.0 в пакете: таблица ошибок из спецификации, `retry` по РП16 (выпуск v0.2.1)
- **Решение:** копия `spec/agent-protocol.yaml` обновлена до ПАО 1.2.0 (agentic-ps-platform@04b7841, sha-256 `4f42e8b62599c88a8291ef3dd797c92e00a4932067eef23271c76943e4407940`). Генератор строит `PAO_ERRORS` из `x-pao-errors` (код → HTTP, `retry`, описание) и отказывает, если перечень не совпадает с `ErrorCode`. Ручной таблицы в заглушке больше нет. Заглушка отвечает по `PAO_ERRORS` и ставит `Retry-After` у 429 и 503. Клиент берёт `retry` из `PAO_ERRORS`, если пара «код, HTTP-статус» есть в таблице, иначе — из тела (код новее версии пакета). `same_key` — повтор с тем же `Idempotency-Key`, новыми nonce и подписью, ожидание не меньше `Retry-After`; `Retry-After` больше потолка или исчерпаны попытки — отказ вызывающему. `new_key` — отказ сразу: нужен новый ключ подписи. У запросов без тела — digest пустого тела (так и было с CO-3). Версия пакета 0.2.1 — совместимое изменение.
- **Почему:** РП16 платформы закрыл расхождения 2–4 пакета: смысл `retry` определён, digest пустого тела записан в §2, таблица ошибок перенесена в YAML.
- **Что меняет:** `spec/`, `src/pao/types.ts`, `src/pao/stub.ts`, `src/pao/client.ts`, `scripts/gen-pao.mjs`, тесты ПАО; CLAUDE.md (таблица модулей), STATUS, ROADMAP. Номер К6 оставлен за решением о хранилищах PostgreSQL (совместный план, CO-1).
- **Отменяет:** в К5 — ссылку на ПАО v1.1 и источник `0bc924e` как текущую копию; трактовку `retry` клиентом CO-3 от 09.10.2026 (`RATE_LIMITED`, `STATE_UNAVAILABLE`, `UPSTREAM_UNAVAILABLE` теперь повторяются).
